### 现状
- 今晚测试,**豆豆的喇叭图标在动但没声音**
- Console 报错: `EncodingError: SystemError ... Unable to decode audio data`
- **已尝试修复**:在 `miniapp/utils/voice.ts` 加了 `base64.replace(/[\r\n\s]/g, '')` 清洗换行符
- **验证结果**:老板反馈"还是不行"

### 排查路径(公司电脑接手时,从这里继续)

1. **先用诊断接口确认 LLM 是好的**:
   - 浏览器访问: `https://你的CloudBase域名/api/v1/health/llm`
   - 应返回 `{config: {baseUrl, hasKey, model}}`
   - 确认 baseUrl 是 `https://ark.cn-beijing.volces.com/api/v3`,hasKey 是 true

2. **Network 抓真实响应**(关键):
   - 微信开发者工具 → Network 面板
   - 让豆豆说话 → 找 `/api/v1/speech/tts` 请求
   - 点开它 → Response 标签
   - **看 audioBase64 字段**:长度多少?是空字符串?还是有内容?
   - **看 Response Headers 的 Content-Type** 和 **Status Code**

3. **可能的根因(按概率)**:
   - **根因A(已尝试,可能不对)**: base64 含换行符(已清洗)
   - **根因B(60%可能)**: InnerAudioContext 在模拟器对 `file://` 协议支持差,改用 `http://` 临时文件 URL
   - **根因C(30%可能)**: 模拟器 MP3 codec 解码有问题,改 `Codec: 'wav'` 或 `'pcm'`
   - **根因D(10%可能)**: TTS 服务端返回的 audio 真的是损坏的(用 base64 解码工具在线验证下)

4. **建议先试的修复**(公司电脑):
   - 改 `server/src/services/speech-service.ts` line 129: `Codec: 'mp3'` → `Codec: 'wav'`
   - 改 `miniapp/utils/voice.ts` line 35: 文件后缀 `.mp3` → `.wav`
   - 部署后看是否解决
   - 不行再换 `pcm` + 写 WAV 头
